# Verifying automatic NYSE decision runs

The four existing GitHub schedule entries run at **08:12, 08:32, 08:52 and 17:30 New York time**. GitHub's IANA timezone follows DST. The three morning launches are retry opportunities (one unique official round per experiment and NYSE session), not three chargeable decisions. The 17:30 launch is settlement only. No historical model decision is backfilled. Existing closing marks for already-held positions may still be calculated; these are not recovered decision rounds or trades.

GitHub documents that scheduled workflows can be delayed or dropped. Timing changes provide more in-window slack, not a delivery guarantee. Do not loosen the 09:15 ET decision cutoff or use a fake time to repair a delayed trigger. After merge and application deployment, verify the next eligible session's actual workflow start and final engine output: a new official round ID, real decision time before cutoff, and four distinct valid model records for that exact New York date. Then verify the corresponding label on the deployed Home and Daily pages. A green outer job, zero fills, previous-date output, or a cached pre-cutoff read is not proof of today's round. All four recorded HOLD decisions count even with no orders or fills.

If GitHub still repeatedly misses the window, propose a separately approved timezone-aware independent scheduler targeting the authenticated GitHub dispatch endpoint with a dedicated least-privilege credential, an in-window guard, idempotency and failure alarms. Validate and budget it in staging before enabling. Dispatch remains GitHub delivery-dependent; if runner queue latency is the failing component, host the unchanged engine in a dedicated scheduled runner instead. Do not turn on a second production lane until concurrency, pricing quota and credential custody are tested. No such infrastructure change is included here.

The website's calendar uses the NYSE-published regular closures for 2026–2028; refresh it when new holiday ranges or special closures are announced. It does not infer a missed result beyond this range.
